Why semantic HTML matters

Published September 27, 2026 by

Hemen Lahkar, hemen@hemen.co.in

Introduction

HTML is full of tags that describe meaning, not just appearance. A <div> is a generic box; a <button> is a button. That difference is huge for accessibility.

The power of the Web is in its universality. Access by everyone regardless of disability is an essential aspect.

— Tim Berners-Lee

As MDN Web Docs says, Semantic HTML is the foundation of accessibility. You can also use highlighted text for emphasis.

Common semantic tags

Here are some tags you should know. Hover over ARIA to see its meaning. Use Ctrl + U to view source. The output is Hello, world!. Variables like x and y are often written in code. 

// Example of a code block
const greeting = "Hello, semantic world!";

Chemical formulas like H2O and math like E = mc2 use sub and sup. You can show edits with inserted text and deleted text. Sometimes strikethrough is used, and underline can be used for proper names in some languages. Use b and i sparingly, and small print for fine details.

For bidirectional text, إيان is isolated, and this text is reversed. Ruby annotations: 漢 (kan). A long word can break with here: supercalifragilisticexpialidocious. Use Product #12345 for machine-readable data.

Semantic vs non-semantic

Comparison of common elements
Non-semantic Semantic Benefit
<div> <header> Landmark for screen readers
<div> <nav> Identifies navigation
<div> <main> Marks the main content
<div> <button> Focusable and announced as button
Use semantic tags first; fall back to <div> and <span> only when no better element exists.

Media elements

These are also semantic: they tell the browser what kind of content they contain.

Did you know?

The <aside> element represents content that is tangentially related to the content around it. Screen readers can announce it as a complementary landmark.

Mark my words: semantic HTML is not just for SEO. It is for people.
